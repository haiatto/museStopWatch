StopWatch の ELF ミニアプリとランチャー

Why · 5 件（ユーザーの言葉） 出荷時ファームにあったデモアプリ（ストップウォッチ、流体シミュレーション、ルーレット等）のようなアプリを、Muse が作って、その場で StopWatch に入れて動かせるようにする。 アプリはを複数入れたり消したりが出来る方がよく、ランチャー的に動かせるとなおよいです。描画だけをさえたいわけじゃないです。Museとの関係は重要ではあるものの、ミニアバターと吹き出しとかで、画面に常駐したりできると便利でよいですが、必ずしもMuseがいる必要があるとは限らないとしたい ではELFで行く方向がよさそう。 とりあえず作りたいものは、ゲームとかUIのあるミニ電卓とか鍵盤とかのアプリ、音や振動、加速度センサーやマイクを使えたり、あとはI/Oもそこそこ使いたい感じはある。 アプリは丸形のアイコンでで、複数並べられる感じがよい。左側のスライド枠とかで設定と反対にあるとよさそう / アプリ消したり更新したりもMuseができる感じ。既存のものを使うよりは、専用のツールの方がよさそう

ユーザーは顔の画面から右へスワイプして、丸いアイコンからアプリを開く。

多いときは縦にスクロールする。

横のページは 3 枚になり、ランチャーが一番左に入る。

起動時は顔のページを出す。

アイコンを長く押すと、名前・版・大きさと、赤い × の削除が出る。

Muse は専用のツールで、アプリを作り、入れ、更新し、消す。

本体は app.api・list・install・remove・run・stop・log の 7 つのコマンドを出す。

noise_control.cpp:1557 · voice.say の登録（この並びに足す）

本体は VM のファイルを読み、アプリ用の新しい領域に保存する。

image_fetch.c:612 · vm_get_range()（同じ読み方を使う）

アプリは 1 つのファイルで、見出し・アイコン・ELF を持つ。

Muse は VM で SDK を取り、gcc を直接使ってアプリをビルドする。

Muse の VM で Xtensa の gcc が動かないときは、どうしますか？

アプリは画面・タッチ・ボタン・音・振動・IMU・マイク・I/O を使える。

API の版 1 に何を入れますか？

描き方は 2 つある。lvgl の部品と、全画面のフレームバッファ。

 frame の描画には、アプリが自分で M5GFX のスプライトを入れてもよい。2026-11-08 の実験で約 56KB だった（work/miniapp-runtime-study-2026-11-08-m5gfx.md）。

出す関数は exports.list の 1 か所で決め、表・ヘッダ・stub を作る。

出すと本体が最大約 0.7MB 大きくなる。

音はミキサーに入り、鍵盤は押した瞬間に鳴る。会話中は止まる。

アプリが落ちても、本体は再起動して顔に戻り、記録を Muse に返す。

アプリは専用のタスクで動き、終了時に本体がタイマーと画面を全部外す。

外さないと、消したコードを呼んで落ちる。

アプリ中は青を長く押すとアプリが終わる。黄は Muse と話す。

普段はスピーカーの ON/OFF のまま。

アプリ中の黄色ボタン（話すボタン）はどうしますか？

アプリは API でミニアバターと吹き出しを出せる。出すかはアプリが決める。

本体はアバター用の関数を出し、Muse の返事もアプリに渡す。

共通: アプリを置くフラッシュ領域と、elf_loader を足す。

0x9F0000 から後ろは今は空き。

アプリ領域の大きさはどうしますか？

 elf_loader（espressif/elf_loader 2.x）が IDF 6.0.3 で動くかは未確認。最初の試作で確かめる。

変えないもの

  • Muse との接続、会話、返事の読み上げ（Sano）、OTA、設定の画面。
  • スクリプト言語（Lua、MicroPython）は入れない。アプリは ELF だけ。
  • アプリ同士の同時実行はしない。動くアプリは 1 つだけ。
  • アプリのサンドボックス（メモリ保護）は作らない。落ちたら再起動で守る。
  • 出荷時デモのアプリをそのまま移すことはしない。例のアプリは新しく書く。
